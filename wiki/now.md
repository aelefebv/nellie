- **🎉 voxel_reassignment optimization audit closed (3 PRs, mask + tree caching in driver, vectorized 1-to-1 matching)** (2026-05-11) — Audit of `nellie/tracking/voxel_reassignment.py` shipped as 3 PRs into `dechao`: PR A — mask + vox caching in `_run_reassignment` driver loop (PRD #217, slices #220 + #221). Pre-rewrite each frame transition called `_get_master_mask(t)` + `_get_master_mask(t+1)`, where each call reads BOTH `branch_label_memmap[t]` AND `obj_label_memmap[t]` from disk. `master_mask_next` of frame t is byte-identical to `master_mask_prev` of frame t+1 (same union, same disk bytes), so cache `vox_prev = argwhere(master_mask)` and rotate `vox_prev = vox_next` at the bottom of each iteration. Saves 2 memmap reads + 1 argwhere per frame after frame 0. Bundled cleanups: `_get_master_mask` dead `mask is None` first-branch logic replaced with `parts = []` accumulator; `_select_best_pairs` empty-return arity bug fixed (3-tuple → 2-tuple to match the populated branch and the caller's unpack). Wall-clock at num_t=2 (one frame transition): 197.2 ms → 191.7 ms; savings scale linearly with num_t. PR B — vectorize `_assign_unique_matches` Python greedy loop into round-based intersection (PRD #222, slices #225 + #226, ADR 0011). Replaces the `for idx_sorted in range(len(order))` greedy loop with a round-based per-prev/per-next argmin intersection: sort once globally by distance; per round identify rows that are simultaneously the per-prev_id argmin AND the per-next_id argmin over the still-active subset (np.unique on the distance-ordered active slice gives first-occurrences = per-id argmin); deactivate kept rows + rows whose prev_id or next_id was claimed; repeat. Provably equivalent to sequential greedy (walked example in ADR 0011). Test bar: SET-equality on kept (prev, next) pairs (not ordered-equality), because round-based returns kept indices in input-row order while greedy returns them in distance-ascending order. **Caveat documented in ADR 0011**: `_assign_unique_matches` is NOT called by `_run_reassignment` (production driver uses `_select_best_pairs` for 1-best-per-target); the rewrite pins the perf-test target (PRD #153 pre-instrumented it as the lead suspect) and is correctness-preserving for any future caller that wants 1-to-1 unique matches with global greedy semantics. Wall-clock: 2D N=10000 3.1 ms → 1.4 ms (-55%); 3D N=10000 3.4 ms → 3.1 ms (-9%); synthetic high-contention N=100000 27.48 ms → 22.97 ms (-16%). PR C — tree caching across frames in high-memory mode (PRD #227, slices #230 + #231). Builds on PR A's `vox_prev = vox_next` rotation: `tree_next` of frame t is built from coords byte-identical to `tree_prev` of frame t+1, so cache the tree handle and identity-check `vox_prev is _cached_vox_for_next_frame` in `match_voxels`'s high-memory branch. Saves 1 cKDTree build per frame after frame 0. Low-memory mode is intentionally skipped — the explicit serialized-build trade-off (frees the first tree before building the second to halve peak memory) is preserved. Direct callers of `match_voxels` (not going through `_run_reassignment`) typically pass a fresh ndarray each call → identity check fails → safe by default. Wall-clock at num_t=2: ~noise (cache never fires at one frame transition); savings scale linearly with num_t (one cKDTree build saved per frame after the first; ~tens of ms per build at N=1M). **Cumulative**: production driver loop now does 1 mask compute + 1 argwhere + 1 tree build per frame after frame 0 (was 2 + 2 + 2). Test count: 36 → 48 voxel_reassignment tests (3 driver + 7 _assign_unique_matches synthetic + 1 equivalence vs reference greedy + 4 tree-cache cache-hit/cache-miss/low-mem-unchanged). One new ADR in `wiki/decisions/` (0011). Wiki article `wiki/tracking/voxel-reassignment.md` updated (new high-memory tree-caching gotcha alongside the existing low-memory serialized-build gotcha).

- **🎉 flow_interpolation optimization audit closed (3 PRs, -37% on neighbor-lookup, -30% on driver, NaN-alignment bug fixed)** (2026-05-12) — Audit of `nellie/tracking/flow_interpolation.py` shipped as 3 PRs into `dechao`: PR A — single-query rewrite of `_get_nearby_coords` (PRD #204, slices #206 + #207, ADR 0010). Replaces the double `cKDTree` query (`query_ball_point` for counts + `query(k=max_k, workers=-1)` for distances) with a single `query_ball_point` + batched `np.linalg.norm` over concatenated per-coord neighbor indices. Caches `self.scaled_check_coords` alongside the tree on rebuild for distance-compute reuse (single multiplication, single buffer). **Bundled NaN-alignment bug fix**: the pre-rewrite `for i in range(len(distances)): if i not in good_coords: continue` loop only aligned correctly when `good_coords == [0, ..., N-1]`; with NaN coords interleaved (routine after the first frame in `interpolate_all_forward`/`_backward`'s terminal NaN propagation), per-coord results landed in the wrong original-index slots. Fix-and-pin per ADR 0010 — `for pos, i in enumerate(good_coords)` is the correct mapping by construction. **`_get_nearby_coords` N=1000: 2.29 ms → 1.43 ms (-37%)**; `interpolate_coord` N=1000: 7.8 ms → 6.9 ms (-12%). PR B — vectorize per-coord loops in `interpolate_all_forward` / `_backward` (PRD #205, slices #210 + #211). Replaces the per-coord Python loop with a vectorized block: NaN-mask, in-place vector-add (forward) / vector-subtract (backward), batched per-frame row block construction, terminal NaN propagation as `coords[~valid_mask] = np.nan`. Preserves the bit-identical per-coord interleaved init/post row arrangement at `t == frame_range[0]` via `block[0::2] = init; block[1::2] = post` stride assignment. Both forward/backward delegate to a shared `_interpolate_all_directional` helper — collapses the two near-identical 70-line loops into one body parameterized by direction (`forward` flag controls update sign and frame-number formula). Type-side: rows now return as `list[list[float]]` (was mixed `[int, int, float, ...]` from per-coord `tracks.append(...)`); all known consumers (`LabelTracks` at `all_tracks_for_label.py:125`) treat id/frame numerically (`int(track[0])` / `np.argsort([track[0] ...])`), non-breaking. **`interpolate_all_forward` N=500: 3.92 ms → 2.75 ms (-30%)**. PR C — bundled cleanups (#214 / #215). Pre-bucket `flow_vector_array` by `t` at `_allocate_memory` (`self._t_to_rows = {int(t): row_indices}` built once via `np.unique` + `np.argsort` + `np.split`); per-frame `interpolate_coord` lookups become O(1) dict reads instead of O(total_markers) `np.where` scans. Drops dead `if nearby_idxs is None: return None` (never returned None). Replaces `np.max(np.array([um*dt, 0.5]))` → `max(um*dt, 0.5)` (no allocation; 0.5 μm floor invariant preserved + pinned). Removes stale "optional GPU acceleration" docstring claim. Deletes the broken `__main__` block (used `self.im_info` outside the class — wiki gotcha previously said "don't run standalone"; now the broken block is gone). **Cumulative wall-clock wins (M2 Pro CPU)**: `_get_nearby_coords` N=1000 2.29 ms → 1.43 ms (-37%); `interpolate_coord` N=1000 7.8 ms → 6.9 ms (-12%); `interpolate_all_forward` N=500 3.92 ms → 2.75 ms (-30%). Test count: 0 → 27 flow_interpolation tests + 6 perf microbenchmarks (file bootstrapped — flow_interpolation was previously unpinned and had no perf coverage). One new ADR in `wiki/decisions/` (0010). Wiki article `wiki/tracking/flow-interpolation.md` updated (`__main__` typo gotcha removed; t-bucketing gotcha added). `_get_vector_weights` / `_get_final_vector` CSR-style vectorization deferred (per-coord `max_k` is small in practice; profile-driven decision per the precedent of hu_tracking Item 5).

- **🎉 hu_tracking optimization audit closed (3 PRs, 28× on moment math, 5.5× on cost matrix)** (2026-05-12) — Audit of `nellie/tracking/hu_tracking.py` shipped as 3 PRs into `dechao`: PR A — two-step batched matmul rewrite of `_calculate_normalized_moments` (PRD #191, slices #194 + #195, ADR 0008). Replaces the `(N, H, W, 4, 4)` broadcast formulation with `images @ x_powers` then `M.swapaxes(1, 2) @ y_powers`; central-moment path uses the same shape with per-N `x_centered_powers` (batched matmul broadcasts the leading `N` dim). `swapaxes(1, 2)` over `transpose(0, 2, 1)` for torch portability (torch.transpose only takes two dims). ~80× memory reduction at typical N=1000 / H=W=21; **28× speedup** on `_calculate_normalized_moments` + **9.5× speedup** on `_get_hu_moments` 3D (the per-3D-frame hot loop that fires the orthogonal-projections + 3× moment-call path). PR B — per-feature streaming + float32 throughout `_get_cost_matrix` (PRD #196, slices #199 + #200, ADR 0009). Drops the `(N, N, F)` float64 broadcast difference matrix in favor of folding each feature's z-score into a running `(N, N)` cost via the new `_zscore_one_feature` helper (sum-of-squares variance, clamped against catastrophic cancellation). ~80× memory reduction; **5.5× speedup** at N=1000. **Cross-backend parity improved as a side effect**: previously `xp.float64` cast silently coerced to `float32` on MPS (the determinism risk PRD #140 § Implementation Decisions had flagged for hu_tracking); now both CPU and MPS run float32 throughout cost-matrix construction, and the MPS equivalence test achieves **Jaccard = 1.0000 on both 2D and 3D** (was already 1.0 in practice but with noted drift risk). `_get_difference_matrix` and `_zscore_normalize` deleted (no external callers; the dechaos wiki's "deferred extraction" note never resolved). Bundled fix for the PR A MPS-incompatible `transpose(0, 2, 1)` regression that PR A's perf benchmarks didn't run before merge — switched to `swapaxes(1, 2)` and re-verified MPS smoke + equivalence. PR C — bundled cleanups (#201 / #202): GPU distance trick (`||A||² + ||B||² − 2 A·B` BLAS replaces the broadcast subtract in `_get_distance_mask`'s GPU branch — drops the `(N, N, dim)` intermediate) + vectorized `_find_best_matches` (`np.flatnonzero` + boolean-mask + `.tolist()` replaces the Python row/col loop; **4× drop in loop overhead** at N=1000). **Cumulative wall-clock wins (M2 Pro CPU)**: `_calculate_normalized_moments` N=1000 36.5 ms → 1.3 ms (28×); `_get_hu_moments` 3D N=1000 118.5 ms → 12.5 ms (9.5×); `_get_cost_matrix` N=1000 113.1 ms → 20.5 ms (5.5×). Test count: 41 → 51 hu_tracking tests (5 moment-math synthetic + 1 moment-math 3D equivalence + 4 cost-matrix synthetic + 1 cost-matrix 3D equivalence + 4 find-best-matches synthetic, plus 2 backfilled perf microbenchmarks). Two new ADRs in `wiki/decisions/` (0008, 0009). Item 5 from the audit (`_match_frames_sparse` two-pass cache) deferred — caching per-row arrays would add 25–500 MB at sparse-mode N without profiler data showing the second-pass recomputation is actually a hot loop.
